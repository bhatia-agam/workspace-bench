# 0094: fast-v2, the fast subset without jailbreak_recognition and agentic_misalignment

Issue #497.

## Why

Camila, 2026-11-17: "exclude jailbreak and agentic". Measured on the fast subset (s3d-rl600,
2026-11-17): the two safety families take 23 to 38 minutes to judge after their readouts land,
against 1 to 13 minutes for the other 22, so they alone hold a fast run above 30 minutes; and
they change no ordering of the measured arms (without them each arm's fast macro moves by at
most 0.028: s3d .535 -> .538, rl-affw .491 -> .497, Q9 .478 -> .484, NLA .442 -> .449,
prompt-only .475 -> .480, J-lens .116 -> .119, logit lens .063 -> .067). agentic's fast
`pair_rate` also moves by about 0.07 between identical runs. `fast-v1` is frozen ("a new subset
is a new versioned file"), so this is `fast-v2`.

## Change

- New frozen file `evals/fast/fast_v2.json`: `version: "fast-v2"`, the 22 family entries of
  `fast_v1.json` other than `jailbreak_recognition` and `agentic_misalignment`, each entry
  identical to v1's (same `bank_sha`, `units`, `read_ids`, key order); `dropped_families` = v1's
  list in its order, then `jailbreak_recognition`, `agentic_misalignment`; every other top-level
  key as in v1. 22 families, 1,823 units, 2,160 read items; no remaining entry has a `positions`
  rule. `fast_v1.json` is not touched.
- `fast.py`: `VERSION = "fast-v2"`; `VERSIONS = {"fast-v1": <v1 path>, "fast-v2": <v2 path>}`;
  `COMPATIBLE = frozenset({"fast-v1"})`. `subset(version=None)` resolves `version or VERSION`
  **at call time** (the module attribute, never a default argument) and calls a loader cached on
  the version string that reads `VERSIONS[version]`; an unknown version raises `SystemExit`.
  `PATH` is removed (nothing may read a path that bypasses `VERSIONS`); tests patch `VERSION`
  only. `entry`'s messages, `fast_header` and `stamp_fast` keep reading `fast.VERSION` at call
  time. `--fast` therefore means fast-v2; fast-v1 is not selectable from the CLI.
- Under `--fast` the two families are skipped like any family outside the subset (`NotInFast`,
  "<family>: not in fast-v2": skipped by `run`, exit 2 in `judge`). `reads.load` calls
  `fast.entry` before it reads the sidecar, so a fast-v1 jailbreak / agentic file never reaches
  the version check.
- Readouts sidecars (`reads.py`, the declared-version check): `declared_fast not in
  {fast.VERSION, *fast.COMPATIBLE}` is the refusal, so a file declaring `"fast": "fast-v1"` is
  judged under fast-v2 for a family in fast-v2 (identical entries, identical fast plan rows and
  `plan_sha`); any other declared value is refused as today; a new file declares `"fast-v2"`.
  The `plan_sha` guard is unchanged. Prompt-only readers return before this check, as today.
  Code before this change refuses a `fast-v2` file and excludes `fast-v2` rows (fail closed).
- Results (`results.py`): a fast row is in the macro iff `fast_subset == fast.VERSION`, or
  `fast_subset in fast.COMPATIBLE` and the row's family is in `fast.subset()` (the same value,
  by the invariant below). Any other fast row keeps today's exclusion `stale fast subset (<v>)`,
  which now covers a fast-v1 jailbreak / agentic row; no new refusal; the fast / non-fast
  refusal is unchanged; `macro["fast_subset"]` stays `fast.VERSION`. An existing fast-v1 results
  directory therefore reports a fast-v2 macro over its 22 rows with no migration (its two safety
  rows are listed as excluded). `fast_header()` prints the current version and family count
  above a table that may list more rows; say so in its text ("rows of other subsets are
  excluded").
- **What is retained and what is not.** The position-reduction machinery (`readplan` `fast_of` /
  `punct_special` / `is_fast_site`, `reads.fast_narrow`, `fast.position_stamp`,
  `runner.stamp_fast`'s `+fast-<kind>` suffix) stays in the code for the frozen v1 file and its
  tests, and is exercised only with `fast.VERSION` patched to `"fast-v1"`: every caller
  (`fast.entry`, `units`, `rescore`, `readplan.plan(fast=True)`, `reads.load`,
  `reads.fast_plan_sha`, `runner.judge_family`, `Producer.run_family(fast=)`, the CLI) uses the
  default version. After this change fast-v1 jailbreak / agentic FAST files and results are not
  judgeable from the CLI and are not in the macro; a fast-v1 run needs the pre-0094 commit. The
  non-fast paths stay untouched (`tests/golden/plan_sha_pre_0090.json` still pins the plans).

## Invariants

- No prompt, fingerprint, cache key or `prompt_version` changes; for each of the 22 families a
  fast-v2 run makes exactly the calls a fast-v1 run made (a cache written under fast-v1 replays
  with 0 new calls) and gives the same value; only the `fast_subset` stamp differs.
- The strict ATI subset (`ati-subset-v2`) is still contained whole (neither dropped family is in
  it).
- `fast_v1.json` is byte-identical before and after.

New tests:
- `fast_v2.json` equals `fast_v1.json` minus the two families (entry-for-entry, key order, the
  `dropped_families` rule, the version string); `fast_v1.json`'s sha256 is pinned.
- `subset("fast-v1")` and `subset()` both load; an unknown version raises; patching
  `fast.VERSION` switches what `subset()` returns (the cache is per version).
- under `fast_v1`: a jailbreak plan row carries `extra.fast == "fast-v1"`, and the v1
  `fast_plan_sha` of jailbreak and agentic equal two pinned literals (nothing else now catches
  drift in the retained machinery).
- `--fast` on jailbreak_recognition / agentic_misalignment: skipped by `run`, exit 2 in `judge`
  with "not in fast-v2".
- a sidecar declaring `fast-v1` is accepted for a fast-v2 family and judged; one declaring
  `fast-v0` is refused; a produced file declares `fast-v2`.
- macro: fast-v1 rows of in-subset families are included, a fast-v1 jailbreak row is excluded as
  `stale fast subset (fast-v1)`, a `fast-v0` row is excluded as before.
- a toy family's cache written with `fast.VERSION` patched to v1 replays under v2 with 0 new
  calls (asserted on the fake `run_calls` call count) and the same value.
- ATI containment under v2.
